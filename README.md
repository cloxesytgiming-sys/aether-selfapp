# AetherPanel v2.1 — multi-account Discord control center

Run and control several user accounts from one dashboard: commands, snipers, quests, DMs, friends,
crypto wallets + live market charts, moderation, and a license-key system so other people can log in
with their own keys and only ever see their own accounts.

> Automating user accounts (selfbots, snipers, quest completion) breaks Discord's Terms of Service and
> can get accounts banned. Use alt accounts and accept the risk.

## Structure
```
dashboard/
├── dashboard.py     Flask app: pages + JSON API (+ CoinGecko proxy, license checks)
├── procman.py       starts/stops one bot-worker process per account   (was manager.py in v2.0)
├── selfbot.py       the worker (discord.py-self): commands, snipers, quests, moderation, crypto, logging
├── manager.py       LICENSE KEYS + keygen Discord bot (writes keys.txt)
├── db.py  tools.py  shared SQLite layer and helpers
├── keys.txt         generated by manager.py (created on first use)
├── templates/       app layout + overview, accounts, commands, snipers, quests, crypto, inbox, friends, servers, logs
└── static/          css/style.css (Google Fonts), js/app.js, img/favicon.svg
```

## Quick start
```bash
cd dashboard
pip install -r requirements.txt        # in a venv with discord.py-self, NOT discord.py
cp .env.example .env                   # set DASHBOARD_PASSWORD (+ the keygen settings below if you want keys)
python dashboard.py                    # http://127.0.0.1:5000
```
Add accounts under **Accounts → Add account → Start**. The dashboard launches and monitors the workers.

## License keys (manager.py)
Log in with the master password (admin: sees every account) **or** a license key (sees only its own accounts).
```
python manager.py gen 7d 5 "for bob"     # 5 keys, 7 days each
python manager.py gen lifetime           # a lifetime key
python manager.py list [all|unused|active|expired|revoked]
python manager.py info AETHER-XXXX-XXXX-XXXX-XXXX
python manager.py extend KEY 30d         # add time
python manager.py revoke KEY             # disables it; the holder is logged out and their bots are stopped
python manager.py run                    # start the keygen Discord bot
```
* Keys are saved in **keys.txt** as `key | duration | created | activated | expires | note | status`.
* Durations: `7d`, `30d`, `90d`, any `<n>d/w/m/y`, or `lifetime`. **The clock starts at the first login** with the key.
* Expired/revoked keys are rejected at login, kick live sessions, and the dashboard stops that holder's running bots.
* `KEY_MAX_ACCOUNTS` (default 3) limits how many accounts one key may add.

**Keygen bot:** create an official bot at discord.com/developers, enable **Message Content Intent**, invite it,
and set `KEYGEN_BOT_TOKEN` + `KEYGEN_ADMINS` (your user ID) in `.env`. Then `python manager.py run`:
`!genkey <duration> [count] [note]` · `!keyinfo <key>` · `!revoke <key>` · `!extend <key> <duration>` · `!keys [valid|all]`.
Keys are DMed to you; only IDs in `KEYGEN_ADMINS` can use it. It talks to Discord directly (aiohttp), so it
works in the same environment as discord.py-self.

## Pages
| Page | What it does |
|---|---|
| **Overview** | Profile (avatar + decoration, banner, display name, username, bio, badges), account age, Nitro type + duration, servers, friends, messages sent, DMs, quests, snipes, latest activity |
| **Commands** | Tabs: General · User & Guild · Utility · Presence · Automation · **Moderation** (ban/unban/kick/mute/unmute) |
| **Snipers** | **Nitro** and **Giveaway** tabs (see below) with history and win counter |
| **Quests** | Every quest on the account: new / available / running / paused / completed, with a quest completer |
| **Crypto** | Live market (all coins, search, charts), trending & movers, saved wallets + portfolio |
| **Inbox / Friends / Servers / Logs / Accounts** | DMs + alerts, friend requests, server list, per-account logs, tokens + start/stop |

## Giveaway sniper
* Only **bot** messages containing a **trigger word** are considered (default: giveaway, gwy, react with, enter,
  hosted by, winners, winner — editable). Text is normalised first, so fancy-font giveaways still match; words
  match on boundaries ("center" ≠ "enter"). A reaction on its own never makes something a giveaway.
* Enters with **one** method: the **Enter/Join button** if there is one, else **one emoji** — 🎉, or the emoji the
  message tells you to use, or the only reaction. If it can't tell which emoji, it does nothing (no more random reacting).
  Messages containing an ignore word (default "ended") are skipped. Edits are handled, with a retry for late buttons/reactions.
* **Win alerts:** a message that pings you and contains win words (congrats / won / congratulations) is logged,
  raises a notification and posts to your webhook (saved server-side, never sent back to the browser).
* Chat: `!gwsniper` / `!nitrosniper` toggle them.

## Quests
Lists the account's quests and can complete **play-a-game** (heartbeats) and **watch-a-video** quests. Discord's
servers time-gate progress, so a 15-minute quest takes about 15 minutes; two quests run at once. Stream and
Activity quests aren't supported. Rewards are not claimed automatically — claim them in Discord.
Statuses: **new** (started in the last 3 days, not accepted) · **available** · **running** · **paused**
(accepted, progress saved, idle) · **completed**.

## Crypto
* Market data comes from CoinGecko (cached; stale data is served if it rate-limits). A free Demo key in
  `COINGECKO_API_KEY` raises the limit. History is limited to 1 year on the free plan.
* **Live prices** stream from Binance's public feed for the coins on screen (USD view); other currencies refresh every 30 s.
* **Wallets:** save public deposit addresses per coin (and network) on the Crypto page or in chat:
  `!crypto <coin>` posts the address, `!crypto list`, `!crypto add <coin> <address> [network]`, `!crypto remove <coin>`.
  Add an amount to see portfolio value. Private keys / seed phrases are rejected — never store them.

## Moderation
`!ban <user> [reason]` · `!unban <id>` · `!kick <user> [reason]` · `!mute <user> [30m] [reason]` · `!unmute <user>`
(mute = a Discord timeout, up to 28 days). They work wherever the account has the permission; reasons go to the audit log.

## AFK fix
Everything the bot sends by itself (the AFK reminder, auto-replies, command output) is tagged, so it no longer counts
as *you* coming back. Only your own real messages clear AFK.

## Notes
* Tokens are stored in the local SQLite file (shown masked). Keep the folder private; don't share `.env`, `keys.txt` or the database.
* Production: set `FLASK_SECRET_KEY`, serve over HTTPS with `COOKIE_SECURE=1`, single gunicorn worker.
* Logs are per account and only about that account's own activity; old v1 logs stay in the database but are hidden.
